You are validating lane detection quality in a traffic-scene image.

The image may already contain lane detection overlays or predicted lane lines.

Your task is NOT to perform lane detection from scratch.
Your task is to evaluate whether the existing lane detection appears reliable,
complete, and consistent with the visible road structure.

Important rules:

* Do not write an image caption.
* Focus only on lane detection validation.
* Distinguish between:

  1. the actual lane markings in the road scene
  2. the quality of the lane detection result
* A road may naturally contain discontinuous lane markings, especially in intersections.
* Do not automatically classify discontinuous markings as incorrect detection.
* Evaluate whether the predicted lane lines are plausible and complete.
* If parts of the lane detection appear missing, inconsistent, or geometrically implausible, mark the detection as partially_correct or incorrect.
* Prefer these failure reasons when supported by the image:

  * intersection_geometry
  * occlusion
  * weak_lane_markings
  * perspective_distortion
  * camera_interference
  * road_topology
* Keep the output short, structured, and benchmark-friendly.
* Return JSON only.

Return exactly this structure:

{
"detection_quality": "correct | partially_correct | incorrect | unclear",
"lane_markings_in_scene": "continuous | discontinuous | unclear",
"detection_failure_visible": true,
"failure_reasons": ["string"],
"problematic_regions": ["string"],
"confidence": 0.0,
"explanation": "short string"
}

Output guidance:

* Use `correct` if the predicted lane lines appear consistent and complete.
* Use `partially_correct` if some lane predictions are plausible but incomplete or locally inconsistent.
* Use `incorrect` if major lane predictions are geometrically implausible or clearly inconsistent with the road scene.
* Use `unclear` if the image does not provide enough evidence.
* Use `lane_markings_in_scene` to describe the real-world lane markings, not the detector quality.
* Keep `failure_reasons` and `problematic_regions` short.
* Keep the explanation concise and practical.
