You are analyzing a traffic lane direction sign.

The sign contains multiple black lane arrows on a white background.
Each arrow represents one traffic lane.
Arrows must be analyzed individually from left to right.

Your task is to extract the lane structure into valid JSON.

Important rules:
- Count all distinct lane arrows.
- Every visually separate lane arrow symbolizes one lane.
- Do not merge nearby arrows into one lane unless they are visually connected.
- Assign lane IDs from left to right using the lower/start position of each arrow.
- Analyze each lane arrow independently.

For every lane arrow determine:
- allowed driving directions (where the one or multiple arrow-heads point to)
- whether an additional restriction sign/symbol is present on the lane arrow
- whether the lane arrow visually merges/points into another lane arrow

Direction Rules - allowed direction tokens are ONLY:
- "left"
- "slight_left"
- "straight"
- "slight_right"
- "right"
- "uturn"
- "unknown"

Use one or multiple directions per lane arrow depending on the arrow-heads.

Examples:
["straight"]
["left", "straight"]
["straight", "right"]

Merge rules
- merge_into contains lane IDs that this lane visually merges into.
- A lane merges into another lane, if the lane arrow is tilted slightly and points towards another lane arrow.
- Use an empty list if no merge exists.
- Only detect a merge if the lane arrow visually tilts towards the other lane arrow.
- Do not infer merges from proximity alone.

Restriction rules
- restriction_present is true if any additional traffic symbol/sign is attached to or embedded in the lane arrow. Otherwise false.
- restrictions signs can be e.g. truck prohibitions or bus lane signs

Uncertainty handling
- If a direction cannot be determined reliably, use "unknown".
- Do not hallucinate missing lanes, directions, or merges.
- Set needs_review to true if the sign is ambiguous or partially unclear.

Validation:
- Check if "lane_count" equals the number of list-objects in "lanes"

Output rules
- Return ONLY valid JSON.
- Include a short explanation for each lane regarding detected direction, restriction and merges.
- Do not use markdown.
- Do not output text before or after the JSON.

Use exactly this schema:

{
"lane_count": integer,
"lanes": [
{
"lane_id": "lane_1",
"position_index": 1,
"directions": [],
"restriction_present": false,
"merge_into": [],
"explanation": ""
}
],
"needs_review": false,
"review_reason": null
}
